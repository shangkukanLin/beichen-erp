### ⚠️ 判据修正（重要：首版判据是错的，别再复用）

首版量的是 `.el-table__body-wrapper` 的 `scrollWidth − clientWidth` 与「末列右边缘 − 表格右边缘」。
但本项目**几乎每张表都把操作列写成 `fixed="right"`（sticky）**：
- 横向滚动实际发生在 Element 的 `el-scrollbar__wrap` 里，外层 `.el-table__body-wrapper` 恒为 0；
- sticky 末列永远贴着容器右缘 ⇒「末列右边缘」差恒为 0。

⇒ 两个指标**全部恒为 0**，首版于是报了「6 页越界 / 最终 0 越界」——都是假象。真实是 **26 页越界**，
直到用户报「成品采购单还能左右滑」才暴露。**教训：判据要选与 DOM 实现无关的量。**

### 三条判据（`scan-table-overflow.ps1` 已实现，逐表同时量）

1. **主判据**：`margin = 表格 clientWidth − 各列渲染宽之和`，`< −2px` 即列放不下（26 页全靠它抓出来）。
2. `scroll` = `.el-table__body-wrapper` 与 `.el-scrollbar__wrap` 上 `max(scrollWidth − clientWidth)`，`> 2` 为真横向滚动。
3. `btnClip` = **最后一列（操作列）**中含按钮单元格的 `scrollWidth − clientWidth`，`> 2` 表示按钮被切成「…」。
   ⚠️ 只查最后一列：其它列的 link 按钮（如仓库名）文本省略是设计内的（配 `show-overflow-tooltip`）。

### 尺寸预算（本机 viewport 1262 ⇒ 内容区 956px；**1200px 窗口 ≈ 894px**）

- 列宽（`width` + `min-width`）合计必须 ≤ 内容区；表格带 `max-height` 时**再减 ~8px**（纵向滚动条占宽）。
- **至少留一列 `min-width`**（Element 只把余量分给 min-width 列 ⇒ 宽屏才撑满），数字/状态列用固定 `width`。
- 操作列预算（link 按钮左右内边距已被全局样式清零，实测约 34px/2 字 + 12px 间距 + 16px 单元格内边距）：

- 全局已把单元格内边距 12px→8px（`styles/index.css`，th/td 选择器提高优先级）⇒ 全站每列省 8px；
  宽表也可用 `size="small"` 达到同样密度。
- **表头文案不要与分组表头重复**（分组已写「退回/换入」时，叶子列写「品质/数量」即可）：既省宽又避免截断。

## 【操作摆放规则】反审核只放详情页，审核留列表（2026-09-24 用户口径，已落地 20 页）

**规则**：`审核`属「正向发起」，留在列表行内；`反审核`属「撤销已生效单据」，只在详情页 —— 列表行内不再出现反审核。

**Why（决定性理由：原因只在上下文里）** 反审核会回滚库存 + 冲销应付/应收 + 反加权成本，风险高；而它的失败原因列表上完全看不见：
- 采购单 `PurchaseOrderServiceImpl.unAudit`：`该采购单对应的应付账款已核销，无法反审核`、冲回库存前校验"库存已被后续单据消耗"
- 采购退货 `PurchaseReturnServiceImpl.unAudit`：`应付账款已核销`、`扣款已转应收，请先反审核对应的转应收单`
- 销售退货 `SaleReturnServiceImpl.assertNotSorted`：`已有货物被退货整理（已整理 X），无法反审核`
- 销售出库/委外交货/盘点的反审核也各不相同。**详情页有上下文、能摆出下游单据；列表只有一行。**
- 附带收益：列表操作列本来就挤（4 个 2 字按钮需 176px），移走一个正好把宽度还给明细列。
- 失败原因无需额外开发即会弹出：`api/request.ts` 统一 `ElMessage.error(res.msg || '请求失败')`（L48/51/62）。

## 【长期规则】草稿态就地可编辑 —— 详情页改 + 存，列表不给「编辑」入口（2026-09-24 用户口径）

**规则**：任何单据只要是**草稿状态**，就必须能在**详情页里直接编辑并保存**；列表操作列**不再提供「编辑」按钮**
（也不再跳独立编辑页）—— 一个动作只留一套入口。

**Why**
- 两套入口 = 两处逻辑要同步维护（字段/校验/联动/权限改一处漏一处）。
- 列表只有一行，看不出"这张单还能不能改、改什么"；详情页有完整上下文（明细、可用库存、金额/税额联动、下游单据）。
- 与「反审核只在详情」同源：**列表放"进详情 / 发起新业务"，详情页放"改与撤销"**。

**实现口径（样板：`purchase/order/detail.vue` 与 `sale/order/detail.vue`）**
- 详情页状态三分：`head`（只读快照：code/status/制单人）+ `form`（可编辑副本，**白名单**初始化：不把 code/status/审核人回传）
  + `items`（**深拷一层**，编辑不污染 head）。
- 草稿分支：渲染 `el-form`（字段与新增页一致）+ 明细可增删行 + 金额/税额/总额**由后端 update 重算**（前端只校验必填/数量>0/单价>0）。
- 已审核 / 已作废分支：保留原只读信息块（`el-descriptions`）。
- 页头操作区：草稿 = **保存**(主) + 审核 + 作废；已审核 = 售后（退货/换货）+ 反审核。
- 保存成功后置该单据的 `*_DIRTY_KEY`，列表按需刷新；后端 update 自带「只有草稿状态可编辑」守卫。
- 列表侧：草稿行只留 `详情 / 审核 / 作废`（审核=正向发起，留在列表 ✓）⇒ 操作列按剩余按钮给宽；
  同时**删掉 `goEdit/handleEdit` 函数与独立编辑路由**（如已删 `inventory/purchase/edit/:id`，组件 `purchase/order/form.vue` 仍供新增使用 ✓）。
