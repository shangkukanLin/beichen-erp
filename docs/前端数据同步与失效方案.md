## 1. 问题与目标

### 现象（用户报告）

| # | 现象 | 触发路径 |
|---|---|---|
| ① | 产品管理**新增产品后返回列表，列表不显示新产品** | 列表 → `/product/add` 保存 → 返回列表 |

> 不要"每次回到页面都刷新"，而是"**相关数据被修改后**才更新页面"。

## 2. 根因

三个现象同源，是**两个机制缺口叠加**的结果：

1. **页面被缓存**：`src/layout/index.vue:287` 的 `<keep-alive>` 几乎全站缓存（只 `exclude` 3 个组件名：`PurchaseAdd`、`PurchaseReturnAdd`、`InventoryWarehouseMoveAdd`），`:key = fullPath + tabSeq[path]`，而 `stores/tabs.ts:86` 的 `tabSeq` **只在新建页签时 +1** ⇒ 两个已打开页签之间切换，组件被复用，`onMounted` 不会再跑。
2. **数据只在 `onMounted` 拉，刷新与否靠逐页手写的脏标志**。谁忘了写，就表现为"要 F5"。

### 改造前的两套（互不相干）机制

| 机制 | 位置 | 缺陷 |
|---|---|---|
| 27 个 `*_DIRTY_KEY`（`sessionStorage`）手写三连：写操作处 `setItem('1')` → 列表页 `onActivated` 里 `getItem==='1'` → `removeItem` + 重拉 | 定义：`src/api/enums.ts:1047-1068`、`src/api/sale.ts:90`；消费模板：`src/views/dev/project/index.vue:107-114` | ①覆盖靠人记得写；②**布尔 + removeItem 只支持一个消费者**：两个页面共享同一 key 时，先激活的把标记清掉，第二个漏刷 |
| `window` 事件 `refresh:dropdown-data`：只清 `RemoteSelect` 的下拉会话缓存 | 派发：`src/layout/index.vue:174-182`；消费：`src/components/RemoteSelect.vue` | **必须用户手动点顶栏「刷新数据」** |

### 三个现象各自的缺口

| 现象 | 现场 | 缺口 |
|---|---|---|
| ① | `views/material/index.vue`（改造前只有 `onMounted(() => { loadBrands(); loadData() })`，**没有任何 DIRTY key**）；`views/material/detail.vue:200-204` 保存后**不置任何标记** | 两端都缺 |
| ② | `RemoteSelect.vue` 的会话缓存 `loadedOnce/cachedAll` 只由手动事件或组件卸载清除；`views/outsource/material-info.vue:147` 新增物料后**只关弹窗 + 刷本页**，不发任何信号 | 下拉缓存无法感知他处新增 |
| ③ | 有的详情页置了 key（`dev/project/*`），有的没置（`material/detail.vue`） | 口径不统一 |

> `src/api/enums.ts:1051` 的注释原文即：*"以下列表原先只有 onMounted、不带脏标志，从新增/详情返回（keep-alive 复用组件）时不会重新拉取，列表会停留在旧数据"* —— 说明这个坑此前用**逐页手写**补过一轮，所以必然有漏网。

## 3. 方案：数据域失效总线

一句话：**把"谁改了 → 谁该失效"从各页面收回到请求层自动完成，页面只负责"我要不要用这份数据"。**

```
写操作(任意页面/弹窗)
      │  POST/PUT/DELETE + 业务 code===200
      ▼
[request.ts 响应拦截器] ──按 URL 前缀查表──▶ invalidate(domain)  ⇒ sessionStorage 版本号 +1
                                                     │（含 DOMAIN_DEPS 级联）
                                                     ▼
    列表页 useDomainRefresh(domain, loader) ── onActivated 比版本 ──▶ 变过才 loader()
    RemoteSelect domain="x"              ── 展开时比版本 ────────▶ 变过则丢弃会话缓存重查
```

### 3.1 数据域（domain）模型

域 = "会被某个页面写、又被另一个页面读"的数据集合。**URL 前缀 → 域**的表是单一来源，位于 `dataFreshness.ts` 的 `URL_DOMAIN`。

口径：正则只匹配**路径边界**（`(/|$)`），所以 `/^\/outsource\/material(\/|$)/` 不会误命中 `/outsource/material-order`；一条 URL 只映射到第一个命中的域（表按具体 → 宽泛排序）。

### 3.2 自动 mark（请求层，关键）

在 `src/utils/request.ts` 响应拦截器的 **`res.code === 200` 分支**内调用：

```ts
invalidateByRequest(response.config?.method, response.config?.url)
```

- 只认写方法（`post/put/delete/patch`），读请求一律忽略；
- **只认业务成功**：本后端业务失败也返回 HTTP 200 + `code ≠ 200`，而这里已是 `code === 200` 分支 ⇒ 失败/字段校验被拦**不会**触发刷新；
- 因此**弹窗式新增（如 `outsource/material-info.vue`）一行都不用改**就自动失效 —— 这正是现象②的根治点。

### 3.3 按需 check（页面层）

列表页标准接法（`useDomainRefresh` 内部：`onMounted` 拉一次 + 记账，`onActivated` 仅版本变化时重拉）：

```ts
useDomainRefresh('product', loadData)
```

> 注意 Vue 的 keep-alive 组件首次进入会 `mounted` → `activated` 各触发一次，所以 `onMounted` 里必须把版本记账，否则首屏会白拉两遍 —— 实现里已处理。

非生命周期场景（弹窗打开、点击查询前判定）用 `createDomainWatcher(domain)`：

```ts
const w = createDomainWatcher('material')
function onOpen() { if (w.changed()) reload() }
```

### 3.4 下拉缓存按域失效（现象②）

`RemoteSelect` 新增可选 `domain` prop，会话缓存的有效性绑定域版本：

```vue
<RemoteSelect :fetch="..." label-key="materialName" domain="material" />
```

**向后兼容**：不传 `domain` 时 `domainVersion(undefined) === 0` 且 `cachedVer` 初值 `-1`，行为与旧版**完全一致**（缓存仅由 `refresh:dropdown-data` 清除）。

### 3.5 域依赖（DOMAIN_DEPS）

审核类操作会跨域影响（销售单审核 → 扣库存 + 生成应收；采购审核 → 增库存 + 生成应付）。用 `DOMAIN_DEPS` 表达，避免"列表更新了但库存页没更新"的新一类不一致。

P0/P1 先留空（本轮三个现象不涉及联动），P3 起按实际审核联动逐步补；**只登记确实会被联动改动的域**，否则会退化成"每次回来都刷新"。

### 3.6 顶栏「刷新数据」按钮语义升级（P3）

现状 = 派发 `refresh:dropdown-data` 只清下拉缓存。建议改为 `invalidateAll()`（全部域版本 +1）：语义 = "我不知道改了啥，全部重来一次"，且不再需要单独的清缓存路径。

## 8. 风险与约定

| # | 事项 | 说明 |
|---|---|---|
| 1 | **`markDirty` 同名不同义** | `stores/pageGuard.ts:27` 的 `markDirty` 是"**表单未保存**"守卫（`useUnsavedGuard`），与数据失效无关，命名上不要混用 |
| 2 | **HTTP 200 + `code ≠ 200`** | 本后端业务失败也返回 200；失效只能写在 `code === 200` 分支内，否则失败也刷新 |
| 3 | `sessionStorage` 不可用 | 隐私模式等场景 `dataFreshness` 内部已 try/catch，退化为"本次不失效"，不影响功能 |
| 4 | 多实例/多页签 | `useDomainRefresh` 的 `seen` 是**每个调用点闭包一份**，同路由多实例互不影响；版本号单调递增天然支持多消费者（这是相对旧布尔标志的改进） |
| 5 | 失效风暴 | 批量导入/批量审核会连续 bump 同一域，但页面只关心"变过没有" ⇒ 版本号天然幂等，无额外开销 |
| 6 | 跨域联动 | 审核类必须先补 `DOMAIN_DEPS`，否则会出现"列表新了、库存页旧了" |
| 7 | 性能 | `domainVersion` 读的是 `sessionStorage`（同步、微秒级）；`onActivated` 判定无网络请求 |
| 8 | 与旧机制并存期 | P2 完成前，同一个域可能同时有 `*_DIRTY_KEY` 与新总线在生效 —— 两者语义一致（都会触发重拉），不会冲突，最多多拉一次 |

## 9. 后续（P3）

### 9.1 域表覆盖度校验 ✅（2026-09-30 已完成）

P2-d 之后刷新只依赖总线，所以"写接口的 URL 是否登记进 `URL_DOMAIN`"变成**单点风险**。为此新增常驻校验：

```powershell
powershell -NoProfile -File tools/regression/audit-url-domain-coverage.ps1
```

它扫遍 `src/**`（`.ts`/`.vue`）里所有 `request.post/put/delete` 路径，归一化模板占位符（`${id}`/`{id}`）后取"到第一个纯数字段为止"的前缀，再与 `URL_DOMAIN` 做前缀匹配，输出未覆盖清单。

⚠️ 该脚本踩过两次坑，都已修并留注释：
1. **结束符假设错误**：用 `Substring(len-2)` 当成 `/>`，而普通 `>` 结尾的标签会少一个字符（吃掉值末尾的引号）⇒ 55+ 文件 `TS1003 Identifier expected`；

> 两条教训：
> - `vue-tsc` 的判据要看**日志内容**，不要信 `cmd /c "... & echo %ERRORLEVEL%"` 的退出码（`%ERRORLEVEL%` 展开时机不可靠，曾误报 `EXIT=0`）；
> - 批量改写源码前先想清楚"**属性值里可能出现标签结束符**"这类反例；幂等脚本 + `git checkout` 可以快速重放（本次两次都靠它恢复到正确状态）。
