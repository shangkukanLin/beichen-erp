## §7｜I27 修复记录（2026-09-18，用户确认后修复）

### 7.1 根因
`FinanceReceiptServiceImpl.audit()` 的核销循环里，**没有排除"预收台账（ADVANCE）"行**：
预收行是"多收款"产生的**负数应收**（`status=ADVANCE`，`unpaid_amount<0`）。当它再次被当作核销目标时，
`newUnpaid = unpaid − amt` 必然 < 0 ⇒ 走"超额"分支 ⇒ **再生成一张预收单**，单号取
`rec.billNo + "-ADVANCE"`；而 `rec.billNo` 本身已经带 `-ADVANCE` ⇒ **后缀层层叠加**，
最终超过 `varchar(50)` ⇒ 审核写库报 `Data too long for column 'bill_no'`，单据**永久卡在草稿**。
语义上"用收款去核销预收"等于**退款**，本就不该走收款核销。

### 7.2 改动（3 处，均为后端；前端无需改）

## 5. 验收标准

1. **UI 断言**：每步有断言（提示语/状态列/明细值），`FAIL=0`；**不允许零断言 PASS**。
2. **落库断言（只读比对）**：单据主表+明细、`warehouse_stock`、`warehouse_stock_log`（含 `related_bill_no/id` 可回溯）、应收/应付/收付款/流水。
3. **对账 5 项**：① 成品 库存×流水 diff=0 ② 物料 库存×流水 diff=0 ③ 应收 = 销售 −（收款＋退货冲减） ④ 应付 = 采购/委外 − 付款 ⑤ 盘点后 `warehouse_stock.quantity == actual_quantity`。
4. **数据留存清单**：阶段 / 单据类型 / 单号 / 状态 / 金额数量，作为交付；与 P0 基线对比证明"只增不删"。
