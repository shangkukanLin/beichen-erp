# ADR-0009: 账单定位为结算单（双通道），财务单据存 ID 查名 + 枚举统一存 code

- **状态**: 已采纳
- **日期**: 2026-08-14

## 背景

财务模块存在三个一致性与规范性隐患：

1. **账单是「死模块」**：`FinanceBill.generate()` 生成后无审核、无作废、无核销，`status` 恒为 UNSETTLED，付款/收款也不回写账单 `paidAmount`，账单与实际收付款脱节。
2. **冗余名字快照**：`FinanceBill.partnerName`、`FinanceReceipt/Payment` 的 name 字段与项目「存 ID 不存名」核心原则相悖，改名后成脏数据。
3. **枚举 code/label 口径不一**：财务模块状态存 code（英文），委外/采购/销售模块存 label（中文），存在踩坑隐患。

## 决策

**1. 账单定位为「结算单」，但保留双通道（向后兼容）**：

- 账单支持审核/作废，审核后可作为付款单/收款单的核销来源
- 付款单/收款单明细既可直接核销应付/应收台账，也可通过已审核账单核销（双通道）
- 账单 `paidAmount` 由核销流水实时回写/汇总，与收付款联动闭环

**2. 财务单据统一「存 ID、查询时 JOIN 查名」，不留痕**：删除 `partnerName` 及各 name 快照字段，前端展示时 JOIN 实时查名。

**3. 枚举统一「存 code（英文），显示 label（中文）」**：财务模块已存 code，维持不变；全项目口径统一记录到 glossary，防止再犯。项目未上线，无历史数据迁移负担。

## 后果

- **正面**：账单形成「生成→审核→核销→结清」闭环；单据名实时准确；枚举口径统一。
- **负面/代价**：账单需补审核/作废状态机 + 核销联动，改造量较大；不保留历史名字快照（改名后历史单据显示新名）。
- **不可逆**：账单从此承担结算职责，需与收付款联动维护。

## 备选方案

- **账单=对账快照（模式①）**：账单仅作对账展示，不影响收付款流程。被否决——无法形成闭环，用户明确要联动。
- **账单强约束（必须先建账单才可付款）**：被否决——改变现有使用习惯，且老数据无账单无法付款，采用双通道向后兼容。
- **财务单据保留名字快照（历史留痕）**：业界财务通常留痕。被否决——用户明确不留痕，存 ID 查名即可。
